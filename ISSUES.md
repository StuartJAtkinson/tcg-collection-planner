The pieces are all present — `PACK_ART` already has the wrapper photo per set and per booster variant, the cards are already dealt whole from a seed before anything is shown, and the reveal is already per-card — so this is presentation over a model that already holds still. - [ ] **The 186px booster square pads the set table with 549 blank rows** — the art is sized by the picture, so a block shorter than 7 rows is padded to fit it (`PACK_ROWS = 7`, a row being 33px at its shortest — 6 for the square, +1 for the Draft chip that now sits above it). It renders fine and the alignment is right — the cost is that a set with no sub-sets now sits in a tall empty band. Levers, cheapest first: a smaller square (124px = 4 rows would roughly halve it), letting short blocks share one gap row sized to the shortfall instead of N whole rows, or dropping the square for the wrapper's own 0.525 aspect. *(found 2026-08-11)*

## Resolved
- [x] **Conflux's collation was unreachable on Windows, because its set code is `CON`** — `CON`, `PRN`, `AUX`, `NUL`, `COM1-9` and `LPT1-9` are device names Windows has reserved since DOS, extension and all. Node's fs reaches past the Win32 layer and wrote `boosters/CON.json` anyway, and then nothing else could read it: `git add` failed with "No such file or directory" on a file `ls` listed happily, and `serve.py`'s `open()` would have failed the same way, so opening Conflux boosters could only ever have come up empty. The file carries a trailing underscore now (`CON_.json`) and `packFile()` applies the escape in all three places that name these files — `gen-boosters.mjs` writing them, `loadBoosters` fetching them, and serve.py's allow-list, whose `[A-Z0-9_]` class already permitted it. Only the FILENAME is escaped; the code inside the json and in `index.json` is still `CON`. Verified: `GET /boosters/CON_.json` -> 200. *(resolved 2026-08-14)*
- [x] **The tear is a strip pulled off in 3D, not a clip sweeping down the art** — the pack's top tenth is cloned into a `.booster-strip` box (`overflow: hidden` crops it, so it sits invisibly over the original at rest) and pulled right to left and slightly up, turned about its right edge with `rotateY` against a `perspective` on the wrapper. The body's cut is a polygon whose right corner drops to the tear line first and whose left corner follows, so the seam travels with the strip instead of the whole top edge going at once. Two things this needed: the clip had to move off the wrapper onto the pack's own `img`, because a clip-path clips descendants and the strip is one — on the wrapper it cut off the very thing meant to fly past the top edge; and the strip's art is CLONED from the live img rather than pointed at `packUrl` again, because in Online mode `trimPack` has replaced the src with a canvas blob and a second URL reference would tear off a white rectangle the pack no longer has (confirmed: the clone's src is `blob:`). The clone's inline sizing also had to be stripped and restated — it beat the stylesheet and rendered the art 18px wide inside a 272px strip. Travel is bounded at -92% so six packs tearing inside the 280px sidebar do not throw strips off the left of the window. *(resolved 2026-08-14)*
