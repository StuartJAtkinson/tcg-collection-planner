## Open
- [ ] **A holding has no language of its own, so an imported foreign copy rehydrates to the catalogue's** — found while answering "we don't have a language column?". Language is a fact about the PRINTING everywhere in the app, and correctly so. It is also a fact about a COPY YOU OWN, and there it is dropped: `rehydrateDecks` matches on `set/number` and keeps only `qty` and `foil` from the stored row, so a Japanese Sol Ring saved as `lang: 'ja'` comes back `'en'` on the next load. Measured live, not reasoned about: stored ja, rehydrated en. It bites because the catalogue is built from `default-cards` &mdash; one row per ENGLISH printing plus the 2,634 never printed in English &mdash; so a foreign copy of a card that also exists in English has no distinct row to match, and the language has nowhere to live but the holding. Same shape as `foil`, which is already carried for exactly this reason. *(found 2026-08-16)*
