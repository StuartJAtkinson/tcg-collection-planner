# Card Collector v2

Catalogue-first TCG collection tracker.

**The UI is `index.html` at the repo root** — a self-contained, hash-routed static
page, served on **http://localhost:5255/**. It is the whole app: every layout,
control and interaction decision gets settled there, against the real catalogue.

There used to be a second surface, a Next.js 16 + Postgres implementation under
`app/` and `src/`. It was deleted in August 2026 once the static page had passed
it on every screen; the bulk downloader it owned survives as `gen-data.mjs`, and
the rest is in git history.

Open items: [ISSUES.md](ISSUES.md) — which is also where the decisions live. Each
resolved entry records what was measured and why the call went the way it did,
so the reasoning sits beside the work rather than in a plan document.

ARCHITECTURE.md and REDESIGN.md are both gone. ARCHITECTURE.md planned the
deleted Next.js surface — `src/pipeline.ts`, eight stage pages, a phase 0 for
`tsc` errors in a repo that now has no TypeScript and no dependencies — and
ISSUES.md was citing it as the plan that would close most of its own items.

## Run the UI

```
python serve.py      # http://localhost:5255/
node build.mjs       # rebuild draft.css after editing classes in index.html
node check.mjs       # headless render harness — run before calling anything done
node gen-sets.mjs    # regenerate sets.js   (needs data/AllPrintings.json.gz)
node gen-cards.mjs   # regenerate cards.json.gz (needs data/scryfall-default-cards.jsonl.gz)
node gen-art.mjs     # cache card art locally  (default: just what #/anatomy draws)
```

No install, no bundler, no framework. `index.html` is one file: a `PAGES` map, one
`render()`, and all state in a single `P` object. `serve.py` is `http.server` plus a
no-store header and a six-path allow-list (it roots at the repo now, so the default
handler would have served `.git/` and `data/`), and one endpoint: `/data-index.json`
reports what is actually on disk, which is what Config's Local column reads. That
exists because a page cannot stat a filesystem, and the hand-typed sizes it replaced
had drifted on five of the eight source rows — one named a filename that does not
exist, one named a file that had never been downloaded at all.

The one thing the page fetches is `cards.json.gz` — **107,214 paper printings of
37,555 cards**, generated by `gen-cards.mjs`. It is too big to inline the way
`sets.js` is, so `serve.py` sends it with `Content-Encoding: gzip` and the browser
inflates it; there is no gunzip in the page. Splitting oracle from printing is what
keeps it to **5.3 MB gzipped** — flat, with every printing carrying its own copy of
the rules text, the same data is 10.2 MB. `CARD_ROWS` in `index.html` is now the
offline fallback rather than the only data: the page renders on the mocks until the
catalogue lands, and `check.mjs` runs with no network at all. `ALL()` is the
catalogue; `CARDS()` is the capped slice a view may draw, because every list here
renders its whole input.

`build.mjs` runs the Tailwind CLI over `index.html` alone — `source(none)` is
deliberate, or Tailwind would walk the whole repo and fold every class it found in
`docs/`, `ref/` or a stray scratch file into the stylesheet. `check.mjs` renders every page in `node:vm` against a stubbed
DOM and asserts the decisions: contrast of card names against every frame, pack
geometry, round-robin thinning, that every declaration is used and every inline
handler resolves. It is the reason the UI can be a single 2k-line file.

`sets.js` is generated — 986 paper MTG sets with `set_type` and a booster-collation
flag, plus `PACK_ART`: 184 sets × their booster products, keyed by the same
collation variant, as TCGplayer product ids. MTGJSON's `sealedProduct` has the
ids; TCGplayer's CDN serves the wrapper photo by id, and the Printings table
shows it in a column beside the month. Regenerate with `node gen-sets.mjs`
(needs `data/AllPrintings.json.gz`).

Those photographs ship on a white card, so they are cut out before they are
shown. `node gen-packs.mjs` fetches all 388 and does that cut ONCE — flood fill
from the border ring to alpha, white balance, levels, saturation — writing
`packs/<id>_<size>.png` (43 MB at 200w, 194 MB at in_1000x1000, gitignored). Config → TCGplayer →
**Local** serves those; **Online** hotlinks the CDN and repeats the same pass in
a canvas on every page. The two produce the same picture because they run the
same code: `trim.js` is loaded by the page with `<script src>` and read by
`gen-packs.mjs` with `new Function`, so the Local/Online chip changes where the
bytes come from and nothing else. It was two hand-kept copies with assertions
holding them level, which is a tax for the life of the repo to avoid one file. A local file that isn't there falls through to the CDN, so an
un-run download degrades to the online behaviour rather than a broken image.

The same file carries `BOOSTER` — the collation itself, from MTGJSON's
`set.booster`, as `code -> [kind, cards, rarest]` for the 179 sets that print a
booster you draft. `kind` is **read, not inferred**: Play Boosters are usually
dated to Outlaws of Thunder Junction (2024-04-19), but MTGJSON has Murders at
Karlov Manor shipping `play` on 2024-02-09, so the date rule mislabelled it —
`packsFor()` now asks the file. Sets older than the play/draft vocabulary carry
an unnamed `default` config (Ice Age, Fallen Empires, Fourth Edition). `cards`
counts distinct printings on the sheets — showcase and borderless are separate
entries, as they are in the collation, so it can exceed a set's Scryfall card
count and is deliberately never shown as a percentage. `rarest` is how many packs
you would open, on average, for one copy of the booster's least common card; the
sheets give a per-card weight, so it is arithmetic, not an estimate — Ice Age
comes out at 1 in 121, which is its 121 rares at one rare per pack.

### Tabs

Five tabs — **Printings, Binders, Decks, Import, Search**. Each is the same shape: a
selector band listing sets / binders / decks, which collapses to a subheader once you
pick one. Search is the one tab with nothing to select — it *is* all cards. Cards
render as **MockCard**: a vector/font-only face (title, mana pips, type line, rules
text) with the Scryfall art crop dropped in, so a card renders whether or not its art
is cached.

Set pages carry a **Boosters** button when the set is actually openable
(`set_type` ∈ expansion/core/masters/draft_innovation, not a sub-set, and MTGJSON has
collation for it — 187 of 986 do), and every row in the Printings table carries the
same trigger on its booster picture. Opening boosters is a **window over the page**,
not a route: it asks what you are opening them for, then draws packs from the real
sheet weights, two rows running left to right, click-to-reveal.

Three shapes, and **the pack count belongs to the format, not to you**: a Booster
Draft is 3 boosters per player, a Sealed Deck is 6. The app used to ask "how many"
and default to 6 for both, which is the sealed number. *Draft* thins the in-flight
packs by N−1 simulated drafters, weighted to high rarity. *Sealed* opens the lot and
keeps the lot. *Booster pull* is not a format at all — one at a time, no limit, the
way it gets done on stream — and is the only shape that may open a **Collector
Booster**, since nobody drafts with those; draft and sealed use whatever the set is
actually drafted with, which `BOOSTER` already reports. Wizards publishes no
collation — the sheets are the community's reverse-engineering, the same data
Draftmancer uses.

### Sources, and working offline

Eight sources in one shape, grouped by what they cost: **catalogue data** is
megabytes and the app is wrong without it; **pictures** are gigabytes and the app
draws a frame without them. Every row answers three questions in the order
somebody asks them — *is it here?*, *where from?*, *what will it cost and what do
I type to get it?*

**Every size on that page is derived from a measured bytes-per-unit, not typed.**
The prose that used to sit there had drifted on five of the eight rows: the
Scryfall row named `data/all_cards.jsonl.gz`, which does not exist; the prices
row named a file that had never been downloaded at all; the font was out by a
factor of six. The status chip is `serve.py` reporting the actual disk via
`/data-index.json`, so "not fetched" is a fact rather than an assumption — it is
what caught both of those.

**Work offline** is one control with two answers, because the difference between
them is 124 GB and that is nobody's default to pick for you:

| | card art | total |
|---|---|---|
| as the app draws it | `art_crop`, 8.1 GB | **8.9 GB** |
| at the fullest size each offers | `png`, 132.4 GB | **133.4 GB** |

Those image figures are measured over 24 printings sampled across the catalogue
(`small` 14 KB · `art_crop` 75 KB · `normal` 104 KB · `large` 169 KB · `png`
1231 KB each). The frame here is drawn in HTML, so `art_crop` is the only part
of a card image this UI can actually use — the larger sizes buy nothing but a
sharper illustration.

Setting a size does not fetch it. **This page is static and downloads nothing**,
which is why each row carries the command rather than a button; it used to carry
a "Download & cache now" button that did nothing at all. A file that was never
fetched falls through to the CDN rather than breaking the picture, so an un-run
download degrades to the online behaviour.

One source cannot go local at all and is **named rather than counted**:
pokemontcg.io, because nothing enumerates the Pokémon catalogue here yet — the
page still runs on mock rows, so there is no id list to fetch against. "6 of 8
offline" with no way to reach 8 is a broken promise.

`node gen-art.mjs [size] [--anatomy | --set CODE | --all]` is the Scryfall side.
It defaults to `--anatomy`: 411 images, 34 MB, which is exactly what `#/anatomy`
draws, so six of every shape of card goes offline for a few hundred requests
instead of a hundred thousand. Note it must send a **real User-Agent** — Scryfall
400s node's default one, and says so only in the response body.

### Card anatomy

MockCard was written for the shape almost every card has — one name, one art
window, one type line, one rules box. That is **85,145 of the 107,214 paper
printings and nothing else**. The other 22,069 are a different *shape* of card,
and until recently the generator threw the difference away: `gen-cards.mjs` took
`card_faces[0]`, dropped `layout`, `full_art`, `border_color` and
`frame_effects`, and every back face with them. A Saga, a split card, a
transform and a full-art basic all arrived as "normal" and drew as the same
rectangle with half the card missing.

The shape is **two independent facts**, both read off the source per printing
and neither inferred:

- **layout** — how many faces there are and where they sit. Four cases change
  the geometry rather than the words: `SIDED` (two physical sides — turn it
  over), `PAIRED` (two faces on one side — split, adventure, flip, prepare),
  `LANDSCAPE` (planar, scheme, split), `BANDED` (saga, class, leveler: a
  numbered sequence, not a paragraph). Everything else — mutate, prototype,
  vanguard, host, augment, meld — differs in its *rules*, not its frame, and
  deliberately has no case.

  A **Saga and a Class are two-column cards** on top of that: a tall art strip
  down one side, the track beside it, and the type line across the bottom —
  mirrored between the two, art right for a Saga and left for a Class. The
  source says so rather than taste: Scryfall crops a Saga or Class at
  **312×752** where an ordinary card gets 626×457, and a Leveler gets the
  ordinary one, which is why a Leveler stays a stacked card with banded text.
  Which frame a card gets is read off the **type line**, not the layout, so the
  127 Sagas printed on the front of a `transform` get it too.
- **treatment** — how the illustration relates to the frame. This is the
  breakout-art problem: `framed` and `showcase` put it in a window; `extendedart`
  runs it to the card's side edges with the frame intact; `borderless` drops the
  black edge entirely; `fullart` puts the art under the whole card with the text
  laid over it; `textless` does that and has no rules box at all.

  **The crop's shape is not in the catalogue, and it is not one shape.** Measured
  across the overlaid classes, Scryfall returns 626×457, 626×747, 684×722,
  745×505, 619×808 and 312×752, and the bulk data says which for none of them —
  only the loaded image does. That is survivable in the art window, whose 5/3.52
  is within a few percent of the common landscape crop, and fatal when the art
  is the whole card: `object-cover` fits a 1.37-wide crop to a 0.71-tall card by
  matching *height*, scaling it 2× and discarding **49% of its width**, which is
  why full-art cards looked zoomed into the middle of their own illustration. So
  the overlaid path does not branch on a ratio it cannot know — it `contain`s the
  illustration over a blurred, `cover`ed copy of itself, anchored to the top so
  the soft filler lands under the type line rather than across the visible top.

Some printings have **no frame to draw at all**. A frame exists to hold a mana
cost, a type line and a rules box, and **3,249 of the 107,347 printings (3.03%)
have none of the three**: an art card, a Jumpstart theme divider whose entire
text is "(Theme color: {G})", a punchcard, a *Poison Counter*. Drawn anyway they
are a name over two-thirds of empty box, which is what art series looked like at
2,649 printings. For those the **printed card is the render** — same wrapper, no
black edge (the scan brings its own), flip control kept, since an art card's back
is the signed print and the point of it.

That test is on the **face**, not on a list of layouts, and the difference is not
academic: `front_card` appeared in the catalogue *after* the rule was written and
was handled without an edit. It is per printing rather than per class, so a class
can be a mix — `double_faced_token | framed` is 77 of 118, and Voja keeps its
frame while the punchcard beside it does not. `#/anatomy` says so on each class.
`gen-art.mjs` carries the same predicate and fetches `normal` rather than
`art_crop` for those rows, since the crop is the one size a whole-card render
cannot use; `check.mjs` lifts that predicate out of the file and runs it against
the same fixtures, so the two cannot drift apart.

Crossed, that is **67 real classes, 52 of them with six printings or more**.
`#/anatomy` draws six of each — strided across the class rather than taken off
the front, because the catalogue arrives in set order and the first six of
anything are six cards from one set printed the same week. Each section names
what the class is *supposed* to look like, so a wrong render is recognisable as
wrong rather than merely unfamiliar.

A double-faced card **draws both sides and hides one**; the ⟳ in its art window's
corner turns it over. No state, no re-render — the card carries its own side, so
the flip works identically in the grid, a binder pocket and the draw window.
Scryfall keys the back off the same id with `/back/` in place of `/front/`, which
is why no second art id is stored. It is a swap and not a 3-D rotate: the card
already sits inside a `zoom: 0.8` body and a `container-type: inline-size`
wrapper, and stacking a third containing block on that arrived mirrored and a
pixel out.

`check.mjs` seeds one printing per family and per treatment and asserts each one
*changes* the frame — a renderer that quietly drew all 67 as a normal card would
otherwise pass every other assertion in the file.

**Compare mode** puts each sample beside Scryfall's scan of the same printing
(`node gen-art.mjs normal --anatomy` — 411 files, 41 MB). Two-sided cards are
shown a side at a time, both pairs stacked, rather than with a flip you have to
keep in step; a printing that has no frame is already its own scan, so it is
shown once rather than beside a copy of itself. Note the scans are **normalised to 488x680 portrait for every
layout** — so a Plane, a Scheme and a split card, all of which you turn sideways
to read, arrive rotated; the compare column turns them back, or the drawn card
looks like it got the orientation wrong when it is the scan that is turned.
